The version statement already in 01 is a planning reference, not evidence of an installed compatible stack. Do not claim “latest stable compatible” based on it. Before the authorized F1 environment task, check official release/support ranges for the selected Python, FastAPI, Pydantic, ASGI server, PostgreSQL driver and migration library. Verify on the intended Windows/CI/container environments: async DB lifecycle, cancellation/disconnect, SSE framing, test-client streaming and migrations. Resolve local image/package acquisition separately from the zero-external-egress rule for routine tests; local PostgreSQL connectivity must remain possible.

At the later approved F2 spike, check LangGraph/core/checkpointer/serializer compatibility and checkpoint migration implications; do not couple its versions to F1 unnecessarily. Before F3 export, check the chosen Langfuse SDK and OTel API/SDK/instrumentation/exporter versions, masking scope, content-capture defaults and shutdown behavior. Use one tested export path. Add a real provider SDK only at its authorized adapter task and verify its retry defaults, tool/result schema, usage/error semantics and cancellation behavior against request budgets. Stable version selection and official documentation checks belong to those authorized tasks, not an F0 install or pinning exercise.

Optional improvements, separate from blocking changes:

- Freeze the eligible-case denominator and hold-out policy before comparisons; with 16 eligible cases, a 90% target means at least 15/16, not a rounded 14/16. Report exclusions before scoring and disclose any reused hold-out cases.
- Record one synthetic fixture ID in diagnostic metadata so an induced trace failure can be reproduced without exporting raw content. Do not use real-user-derived IDs as fixture labels.
- Keep the catalog size approximate; inspectability, feasible envelope coverage and provenance matter more than reaching 40 records. Do not expand the domain to fill a quota.
