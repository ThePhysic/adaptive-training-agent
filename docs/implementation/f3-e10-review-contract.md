# F3-E10 — Synthetic blinded review contract

2026-10-27. Offline dummy-only implementation. This is additive review-record
handling authorized by the E10 task, not an amendment to E6/E9 execution ownership.
No genuine participants, cases, custody/authentication, source release, money,
final freeze or real study is approved.

One exact E9 Collection supplies native immutable replay results. Existing
run_case(template) computes the deterministic counterpart and common hard score.
Use the exact ten selected public profiles only. The primary20-pair design is
preserved; the ten future independent cases are absent/unopened, never fabricated.
Two fixed dummy-reviewer labels cover40 public-practice slots/120 dimension slots;
they are not people, signatures or an approved genuine reviewer allocation.

## Packet and binding

A seeded deterministic order/A–B orientation, opaque pair IDs and canonical packet
commitment reproduce the same content. Actual template execution's elapsed timing
is excluded from identity. The hidden local operator bundle binds review/execution
configuration, selection, rubric, exact E9 first-result snapshot, case/variant
mapping, output evidence and packet bytes. The packet ID and private mapping bind
submissions to cases/configuration/variants without revealing those labels on forms.

Reviewer content contains rubric ID, supported preferences and uniform plan-day
views under A/B only. No scores, hard verdicts, eligibility flags, case/source/model
labels, expected judgments, usage, billing, credentials, native reasoning or hidden
mapping. Practice/schema notices are outside reviewer content. Pairs lacking two
complete, hard-passing eligible outputs are omitted from the packet; their slots
remain in the operator report. Do not show placeholders identifying which side
failed. Public seed/data make motivated reidentification possible: this is metadata
blinding practice, not proof of effective human blindness or independent custody.

One packet issue is pinned by an exclusive fixed-path file and a constant SQL key.
Existing identical issue returns it; changed/partial/uncertain issue cannot reset
or replace it. Later automated evidence/source changes invalidate further imports
instead of silently changing the review population. Stop automatic evaluation
before issue. No stale-source or partial-case result is silently filled in.

## Dummy import ownership

Only bounded duplicate-key-safe UTF-8 JSON, dummy-blinded-review-v1,
synthetic_dummy_not_human, the existing rubric, exact packet/pair/A–B assignment
and fixed dummy reviewer are accepted. Rated submissions reuse validate_ratings:
three integer1–5 dimensions, clarity null. Abstentions require a categorical reason
and all ratings null. Pending/missing fields are not ratings. Unsupported fields,
genuine/unopened labels, wrong packets and invalid values reject without raw
payload/error logging. No input path, free-form notes or genuine importer exists.

First **valid** submission owns each `(ordinal,label,dummy reviewer)` slot.
Invalid attempts append only a bounded classified audit event; they do not create
an accepted judgment or replace anything. After validation, an exclusive fsynced
slot fence precedes acknowledged SQL claim, then an owned update-once result commit.
Source, packet and automated snapshot are rechecked after waiting for the claim.
Exact committed duplicates return duplicate status; changed submissions conflict.
Pending/corrupt claims and partial files stop, never delete/reset/reuse. A changed
packet/configuration/output directory cannot select a new slot. Claim and result
transactions are shielded and awaited; cancellation/uncertain commits retain the
claim. Readback does not complete an interrupted import or invent a judgment.

There is no general import writer: finalization is an internal closure over the
validated submission. Experimental SQL lives only in existing disposable test
schemas; no production migration/service. Audit has a noncycling128-event ceiling;
unavailable/full audit fails closed on the attempted audit operation. No raw
submission, private identifiers or payload hashes enter its finite event records.
Packet and slot commitments remain local operator metadata, not ordinary telemetry.

## Reporting and trust limits

Consolidation separates actual local template/replay evidence, dummy submissions
and absent genuine-human evidence. Public-practice denominators stay40 slots/120
dimensions; rated, abstained, missing, indeterminate and ineligible pairs remain
distinct. Invalid/conflicting attempts do not remove planned slots. Dummy-only
means use only validated dummy ratings; genuine-human count is0 and quality null.
No dummy result can populate a genuine aggregate, and no negative/first result can
be replaced. Missing genuine reviewer allocation is explicitly unknown.

Filesystem/SQL source bindings are local integrity controls, not human identity,
independence, signatures or resistance to an administrator altering both stores.
Durability tests cover process restart and controlled faults, not all power loss.
Windows native async SQL needs a compatible selector loop. No OS isolation claim.
Runtime packets/mappings stay in disposable SQL or ignored reserved private paths;
public review archives contain source and numerical dummy report only.

Freezev5 is additive and unapproved. Earlier candidates and all hard rules remain
unchanged. Genuine authoring/custody/opening, reviewer appointment/collection,
provider/privacy/money/execution and final freeze are still separate approvals.
