## Proposed next task — F3-E1: Offline Counted-Probe Evidence Rehearsal

**Objective:** close one demonstrated evidence-collection seam before spending
or live execution. Produce common-scored, provenance-correct artifacts from the
existing counted single-probe assembly, preserving intermediate hard failures and
unknown financial liabilities. This is a proposed new unit name, not a renaming
or reopening of an accepted milestone.

### Why this is a concrete gap

- `scripts/evaluate_models.py` and `experiments/model_evaluation.py` currently run
  the 50-case template/fake/**uncounted** replay suite. This is correct for their
  approved scope; it is not a broken accepted feature.
- `providers/probe.py::SingleProbe.run()` returns an unpublished `RunResult` from
  the existing counted Agent. Its exact fixed input/provider binding must stay.
- `experiments/model_scoring.py::Observation` requires checked tool verdicts,
  intermediate proposal schema/domain verdicts and exact counters. `score()`
  already checks count<=3, generation<=3, combined<=6 as well as other limits.
- `model_evaluation.py::Recorder`, `RecordedTools`, `proposal_checks` and existing
  fixtures supply reusable mechanisms. A final valid RunResult alone can conceal
  a rejected/repaired intermediate proposal; defaulting missing verdicts to true
  would produce misleading hard passes. A final plan or a source label is not
  sufficient evidence.

### Exact proposed scope and files

1. Audit the existing recorder and counted session observation points, then add
   the smallest experiment-only adapter to derive a strict Observation plus the
   existing versioned manifest from **observed** proposal/tool/terminal facts.
   Preserve all original checks and reuse `score()`, not a second scoring engine.
2. Run only the fixed synthetic probe through existing exact MockTransport and
   at least one controlled LocalTLS/native-PostgreSQL simulation fixture. Reuse
   the existing isolated test schema/authority-fixture setup. Positive synthetic
   accounting is not a positive monetary authority or replay-to-live conversion.
3. Add bounded read-only accounting evidence: operation counts, known/unknown
   usage, charged/held amounts and discrepancy flags, sourced from authoritative
   simulation ledger records. Missing evidence stays unknown; no invoices,
   credentials, private project/account/grant IDs or opaque native state exported.
4. Label all artifacts `replay`/`authority_fixture` with the counted protocol and
   synthetic quotes explicitly recorded. Never label them genuine live/human
   evidence. Keep detailed synthetic review artifacts separate from normal traces.
5. Rehearse only named local fixtures and inspect them offline. No real-provider
   input importer/collector CLI, arbitrary case selector, new network transport,
   generalized task runner or automatic batch is introduced.

Relevant existing components:

- `src/future_training/experiments/model_evaluation.py`, `model_scoring.py`,
  `model_review.py` and `scripts/evaluate_models.py` — reuse common contracts and
  checking; keep the 50-case run and historical snapshots unchanged.
- `src/future_training/providers/probe.py`, `counted.py`, `counting.py`,
  `responses.py`, `observations.py` and existing authority fixture tests — inspect
  first; use bounded existing observation seams where possible. A narrow internal
  observation hook is acceptable only if needed, without changing accepted provider
  types, business semantics or exposing arbitrary execution.
- `src/future_training/persistence/authority.py`, `spending.py` and native tests —
  read fixture liabilities using the existing interfaces; no migration expected.
- Add focused experiment tests and a small evidence/handoff document. Prefer one
  adapter module if needed, not shared-package extraction or a new dependency.

**Out of scope:** edits to `gates.py`, `sender.py` live denials, live activation,
pricing policy/rates, permit issuance semantics, private identities, IAM, Terraform,
S3, hosted export, external participants, new domain rules, candidate publication,
approval writes, production orchestration or frozen data. Do not expand the fixed
probe to many cases merely to exercise the collector. A5 handles future sealed
manifest support separately; current Case literals are not silently widened here.

### Acceptance tests / definition of done

1. Existing first-tool/continuation fixture produces one independently validated
   unpublished final plan and a common-scored Observation with 2 count +2 generation
   and 4 combined operations. Checked tool evidence comes from real fixture
   dispatch, not a hand-authored success verdict.
2. Three-generation repair fixture records 3/3/6, one repair, all intermediate
   checks and a hard failure if any intermediate proposal was invalid, even when
   final validation/handling succeeds. No quality number overrides that failure.
3. Unknown/write/owner-bearing tool and malformed/duplicate/native-terminal
   fixtures produce bounded classified outcomes; missing observations cannot
   default to passing arguments, schema, ownership or no-publication assertions.
4. Count mismatch/usage unknown, transport interruption, timeout/cancellation and
   shutdown produce honest missing/uncertain evidence; no automatic retry or
   second logical request. SQL retains required held liabilities and freezes.
5. Local MockTransport and TLS versions produce equivalent non-timing verdicts
   for the same fixture. Native SQL evidence is distinguished from in-memory and
   authored fixture expectations. No production tables/records are used.
6. Privacy canaries absent from both configured local telemetry sinks and shared
   manifests; raw reasoning, billing bindings, credentials and payload hashes do
   not enter reports. Explicit local synthetic plan artifacts remain separately
   labelled and bounded under existing retention rules.
7. Mutation/provenance tests reject an authority fixture relabelled as actual
   live evidence. A source string is not verified origin. Any irrecoverable
   observation gap produces a failed/incomplete record, not invented metadata.
8. Both independent live/financial hard denials and fake-default HTTP application
   remain intact. No new entrypoint accepts credentials/default HTTP transports.
   Terminal-only publication and atomic approval/Submit tests are unchanged.
9. Run applicable targeted Python and native PG/TLS regressions, contract drift,
   40-case baseline and 150-case comparison checks, lint/format/source grammar.
   Frontend/build/full integration checks apply if relevant code changes; report
   exact executed denominators and preserve frozen artifacts/old manifests.
10. Handoff includes one successful and one failed local fixture artifact, source/
    schema/config/lock provenance, observed counters/liabilities, limitations and
    public-source review ZIP. No claim of real provider compatibility or quality.

Dependencies are already installed project/test components and local PostgreSQL;
no new SDK, external service or cloud account should be necessary. Owner must
authorize this implementation unit separately. **No external/provider/hosted/AWS
authorization is necessary to implement it offline.** If preserving the exact
probe/source barriers would require a broader activation model, stop and report
that design issue instead of relaxing a gate.

Done means this evidence seam is locally demonstrated and reviewed, **not** that
F3 is live GO or that remaining human/sealed/hosted/AWS goals are complete. Do not
extend the unit into A2–A9 automatically.
