## How observations are obtained

1. `Rehearsal` accepts exactly an unused `SingleProbe` with exact `ResponsesProbe`,
   `AuthorityLedger(execution='simulation')`, synthetic count quote and exact
   HTTPX MockTransport or existing LocalTLS. It rejects live/effective source
   substitutions, other transports, subclasses and existing execution overrides.
2. It temporarily decorates **only that provider instance's** session factory and
   the one returned exact ProbeSession's admit/complete methods. No global class
   patch, accepted provider-type expansion or production observer API exists.
   Every wrapper calls the original method unchanged; original request bytes,
   responses, budget accounting, validation, retries and transport are not replaced.
3. Normalized completed responses provide bounded proposal verdicts via existing
   strict parser/`proposal_checks`, and checked tool-intent verdicts via existing
   `check_call`. No native encrypted state, tool arguments or raw model body enters
   shared diagnostics. Private call correlation data exists only during the run.
4. On the next admit, the Agent's actual continuation messages contain the results
   produced by dispatch and checked before insertion. Correlate them to the
   observed calls and recheck with `ReadTools.checked_bytes`. These are actual
   local fixture dispatches, not expected-output flags. A result not delivered
   before interruption remains missing; dispatch counts/call coverage expose it.
5. Repair messages generated by the original Agent mark the preceding proposal
   rejected. This captures unsupported semantic clarification fields even when a
   broad JSON/Pydantic check alone accepts the shape. Intermediate hard failures
   remain in proposals and aggregate Observation verdicts after a valid repair.
6. Actual RunResult supplies terminal output/state, numeric usage and request
   counters. Verify response/tool/repair and SQL-claim count coverage. Missing
   observations, uncertainty, frozen/reconciliation/disabled state or cleanup
   gaps make evidence incomplete and force false proposal verdicts. Cancellation
   without RunResult has **no Observation and no score**, not an invented error.
7. Reuse the existing frozen case matching the fixed compatibility profile and
   the existing `score()` unchanged. Quality remains null. The reused manifest
   is explicitly a **one-case** counted-fixture manifest; full dataset metadata
   remains reference provenance, not evidence of executing fifty cases.
8. Original `SingleProbe.used`, the simulation authority's durable single-run
   binding and adapter one-shot guard remain. Concurrent/repeated ownership is
   rejected. Methods are restored and raw correlation data cleared in finally
   paths. Cancellation propagates after bounded evidence cleanup; no background
   recovery, second logical request or auto replay.

The adapter observes normalized provider responses, **not raw malformed native
frames rejected before normalization**. Those failures produce missing-response/
incomplete evidence rather than guessed proposals. Unknown observations never
default to valid. The unchanged fixed probe has no candidate store/approval
authority; its internal terminal is not HTTP SSE done. Positive native tests also
assert zero approved-plan records and zero active monetary authority in their
isolated schemas.

## Accounting, persistence and provenance

`accounting()` uses the existing probe connection/table routing, exact private
specification selectors and a consistent repeatable-read READ ONLY transaction.
It selects at most seven operation/discrepancy rows and rejects anything beyond
the allowed six, with a five-second outer/three-second SQL bound. No call to
`reconcile_mixed`, `_owned`, issuance, claim, settlement or unfreeze is made by the
reader. The original probe alone performs its established simulation transactions.
Native tests assert SELECT/SET-only reader statements and an unchanged local
reconciliation fence and operation rows.

Shared evidence contains ordinal/kind/state, bounded numerical usage and amounts,
finite discrepancy reasons and freeze/disable flags. Project/account/operator/
grant/session/pair/run identifiers and private fingerprints remain SQL selectors,
never fields in shared reports. Generation-reported usage is retained separately
from settled SQL usage, including mismatch observations; no clamping or counting
cumulative stream snapshots twice.

Known generation charges and held count/generation reservations are distinct.
Successful counts remain `responded_held`; no tariff or invoice is inferred.
`actual_total_micro` is null while holds remain. A commit fence makes unresolved
`held_micro`/`liability_micro`/actual total null even if a committed snapshot looks
empty; `committed_liability_micro` is only the observed committed subtotal. A failed
read yields unknown/null, never zero. Known committed charges are not an assertion
of the final total. All microdollars are **synthetic fixtures, not money**.

Packets label replay/authority_fixture, simulation_not_money, unverified model
quality, no collected human/judge scores and no hosted export. Manifests reuse
dataset/catalog/prompt/schema/rate/code/lock provenance and add adapter/fixture
source hashes and actual mock-versus-loopback-TLS type. No runtime payload hash
is introduced. Public files project metadata only; detailed synthetic plans are
local, not telemetry or hosted dataset uploads.

Packets are <=128KiB; responses/proposals <=3, tool intents <=12, observed dispatched
results <=4, bounded request/response observation inputs and SQL rows. Artifact
storage is confined to ignored `.cache/f3-e1`, rejects links/path escapes, and uses
exclusive create, flush/fsync and one persistence attempt. Partial/ambiguous files
are retained and rejected as complete evidence; no retry/overwrite or rerun is
enabled. Caller receives a fresh decoded copy; changing it cannot alter the
adapter's stored bytes. `validate_packet()` checks synthetic provenance,
observation/score/accounting consistency and returns only a fixed error on failure.
It is **not cryptographic origin authentication** or a real-capture importer.

Local full packets: `.cache/f3-e1/evidence/success.json`, `repair-failure.json`,
`cancelled-incomplete.json`. They were copied exclusively from source/fixture-hash
matched final tests and validated. Earlier task development packets remain local,
not overwritten or pooled into acceptance. Retain detailed synthetic artifacts
14 days then explicitly review/remove exact paths; no automatic deletion. File
mode 0600 is not an independent Windows DACL/encryption attestation. No real private
material is allowed in this experiment. The public projections are labelled
synthetic metadata and intentionally omit full plan content.

## Adversarial findings and regression coverage

- A valid final plan could hide an earlier invalid proposal: retain each proposal
  and actual Agent repair rejection; both domain-invalid and structurally valid
  unsupported-clarification repairs remain hard failures.
- Missing recorder/tool data could inherit default true flags: compare actual
  counters/call coverage, force false flags and incomplete status. No terminal
  result means no fabricated score. Common scorer is unchanged.
- A read-only snapshot could report zero during an unresolved COMMIT: use explicit
  unknown unresolved totals, preserve the fence, and test lost acknowledgments
  plus real retained open PostgreSQL transactions. Reader cannot reconcile.
- A reused manifest could imply fifty executions: override selection/IDs to one
  fixed case and label actual local transport/fixture sources.
- A nested manifest or source label could suggest live authority: reject live
  top-level/Observation/manifest labels and non-simulation execution/transports.
  No label alone proves origin; no live import API was added.
- Test observer ownership could cause another execution: reject method overrides,
  repeated/concurrent ownership; call the original probe once; restore only owned
  instance methods. Existing live/financial denials are byte-identical and their
  independent-denial regressions pass.
- Raw exception/canary content could escape on shutdown/storage failure: no new
  logger/exporter; store finite reasons/numbers and normalized supported fields.
  Both configured local sinks and packet projections are canary-tested.
- Partial write or fsync failure could appear complete/retryable: retain partial
  bytes, strict JSON/consistency checks, exclusive create and used flags; no second
  transport or logical request follows failure.

Coverage also includes unknown/write/owner-bearing/invalid tool requests, duplicate
JSON/native calls, malformed/incomplete/refusal terminals, count/usage mismatch,
missing usage, exhausted attempts/input/output, controlled timeout, cancellation,
shutdown, close failure, missing observations, accounting-read outage, provenance
mutation and held-cost manipulation. Fakes are labelled; native SQL assertions are
distinguished from reference/model tests.

Limits: this is an observer for a trusted, controlled fixture process, not an OS
egress sandbox or cryptographic execution attestation. Custom fixture connection/
backend implementations remain trusted; exact transport type alone cannot prove
a malicious Python callback does not access the network. Routine test socket
guards and controlled loopback fixtures provide the measured boundary. Complete
tool evidence arrives only in continuation context; an interrupted dispatch may
remain incomplete. Raw rejected native frames are not reconstructed. Git/manifest
metadata acquisition and artifact filesystem operations reuse local trusted tools;
the provider's 30-second generation deadline does not claim an end-to-end evidence
packaging SLA. No scale, physical-crash, real-provider or invoice claim follows.
